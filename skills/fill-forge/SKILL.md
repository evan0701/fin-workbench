# fill-forge · 铸表技能

把"源表 × 目标表"的月度重复动作，铸成一个可复用、可审计、可交接的填写技能。

> 铁律来源：fin-audit 的零信任原则。本技能铸造的每一个填写技能都必须继承下面的四条铁律，一条不能少。

## 何时用我

- 每月/每季要填一张表：统计局台账、国资快报、集团合并底稿、银行资金计划表、行业报送表……
- 目标表的数据可以从科目余额表、财务报表、序时账等导出文件中取得
- 同样的"取数 → 填格 → 核对"每月重复一次以上

## 铸造五步（严格按顺序，不可跳步）

### 第一步 · 收集三样材料

| 材料 | 必需 | 用途 |
|---|---|---|
| 目标表模板（含填报说明/口径文件） | ✅ | 决定填什么、填到哪 |
| 数据源导出文件（余额表/报表等） | ✅ | 决定从哪取 |
| 上期人工填好的成品 | 强烈建议 | 反推映射关系 + 回填考试的考卷 |

缺上期成品时：仍可铸造，但第五步改为"本期双人复核"，并在 SKILL.md 标注 `未经回填考试`。

### 第二步 · 生成映射草稿（AI 辅助，人只审不填）

1. 读目标表填报说明，列出每个待填字段的**口径问题清单**（期间口径？含税/不含税？累计/当期？）
2. 对数据源跑 `fincore parse`（如已接入）或人工确认列结构，产出映射草稿
3. 拿不准的字段**必须**列入"待确认问题清单"交用户，禁止猜
4. 衍生字段（源表没有直接对应的，如"营业利润""实缴税费合计"）：写明计算公式 + 口径依据，一并交确认

### 第三步 · 人工确认映射审核表

渲染成 Markdown 审核表，逐条确认后冻结为 `mapping.yaml`：

| 序号 | 目标表项目 | 目标单元格 | 数据来源 | 取数口径 | 源示例值 | 目标单元格是否有公式 | 是否填写 |
|---|---|---|---|---|---|---|---|

含公式/衍生计算的行，公式文本直接写进审核表。

### 第四步 · 铸造技能包（统一骨架，禁止自由发挥目录结构）

```
skills/<target-name>/
  SKILL.md          # 用 templates/SKILL-template.md 生成：触发词、输入输出、铁律引用
  mapping.yaml      # 第三步冻结的映射配置（目标单元格 ↔ 数据来源）
  fill.py           # 确定性填写代码：只调 fincore 标准模型 + openpyxl 写值，无 LLM 参与
  references/       # 填报说明、口径说明（衍生公式逐条给依据）、特殊事项
  tests/            # 回填对照测试（第五步的考卷）
```

### 第五步 · 回填考试（全对才上岗）

1. 取**上期**数据源 + 上期人工成品
2. 运行新铸技能填写上期数据
3. 逐格对照：差异清单逐项解决，**差异清零**才算铸成
4. 考试结果记录进 SKILL.md（考试期间、对照文件、结论）
5. 之后的每月运行输出必须附带**复核清单**（每个格子：直接取数 / 衍生计算 / 待确认三类标记）

## 铸出的技能必须继承的四条铁律

1. **锚点不全绿，不填报**：数据源解析的锚点校验（借贷平衡、跨月衔接等）有任何 FAIL，拒绝填写并报告原因
2. **零信任独立取数**：所有数值由代码从标准模型计算，禁止照抄任何"看起来像"的数字；衍生公式必须与 references/口径说明.md 逐字一致
3. **只填数值不动格式**：不修改目标表公式、格式、隐藏行列；目标单元格有公式时跳过并在复核清单标注
4. **只增不严**：用户反馈的填写错误 → 新增校验规则进错误模式库，禁止放宽已有规则

## 红线

- 对外报送表（统计、税务、国资）：产物一律标注"草稿 + 复核清单"，报送前人工复核
- demo 与开源示例只用虚构数据；真实单位名、真实金额不得进入仓库
- 生成的填写技能不做"自动报送/直连申报"，止步于成品文件

## 参考实现

第一个铸出的技能：`forged/stat-monthly-ledger/`（虚构统计月度台账，含完整回填考试）。
铸造新技能时照抄它的骨架，只换 mapping.yaml、fill.py 的映射段和 references/。
