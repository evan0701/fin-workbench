# 视图开发规范（fincore 设计系统 v3）

> 本文档沉淀 2026-10 UI v2/v3 两次迭代的设计约定。任何新增视图（往来账龄、预算执行、老板问答……）
> 必须遵循本规范；改动 `fincore/render.py` 共享层前先读本文。

## 红线（不可突破）

1. **单文件、零外链**：不引任何 CDN/字体/JS 库/图片外链。测试用正则断言 `https?://` 不出现在产物中。
2. **服务端渲染优先**：数字以万元文本直接渲染进 HTML（无 JS 环境可读、可打印），
   同时每个数字单元格/卡片带 `data-v`（元，原始值）供排序与单位切换使用。
3. **锚点全绿才出页**：视图从标准模型渲染，模型 meta 里的 `anchor_results` 必须展示为徽章；
   FAIL 的模型不该走到视图这一层。

## 共享组件（fincore/render.py）

| 组件 | 用途 | 关键约定 |
|---|---|---|
| `html_page(title, meta_items, anchors_html, body, page_js)` | 整页骨架：深蓝顶栏 + meta + 锚点徽章 | `page_js` 必须是普通字符串（非 f-string），动态值用 `.replace("__X__", ...)` 注入 |
| `kpi_cards(items)` | KPI 指标卡行 | 数值用 `value_yuan`（元，自动可切单位）；组合值用 `value_html`（内嵌 v-num/v-unit）；纯文本才用 `value` |
| `num_cell(value, title, bar_pct)` | 数字单元格 | `data-v` 存元值；`title` 放行级溯源；`bar_pct` 加比例条 |
| `anchor_badges(results)` | 锚点校验徽章 | PASS/FAIL/SKIPPED 三色 |
| `SORT_UNIT_JS` | 排序 + 单位切换共享 JS | 切换单位必须覆盖 `td.num[data-v]`、`.v-num`、`.v-unit`、`.unit-tag` 四类元素 |

## 交互约定

- **单位切换**：默认万元；`toggleUnit()` 同步表格、KPI 卡、单位标注。数字条件筛选（列筛选输入框）恒以元为单位，避免切换歧义。
- **排序**：`th.sortable` 点击排序，读取单元格 `data-v`；合计行 `class="total"` 不参与筛选与排序，始终可见。
- **列筛选（Excel 式）**：表头 `▽`（`th[data-col]` + `button.fbtn[data-col]`）；文本列勾选值（面板内搜索+计数+全选），数字列条件（大于/小于/等于/介于 + 该列非零）；实时生效、激活列 ▽ 高亮；与快捷筛选片/搜索叠加过滤（全部 AND）。
- **筛选方案**：`snapshot()` 打包全部条件 → localStorage 持久化，key 按 `文件名:公司` 隔离，上限 12 个；受限环境退化为内存并保持可用。
- **快捷筛选片**：`.chip` 组，单选互斥（含"全部"），状态进 `state`。

## 财务表格规范（承 financial-tables 技能）

数字右对齐 + 千分位（`font-variant-numeric:tabular-nums`）；零值显 `—`；负数标红；
斑马纹 + 悬停高亮；表头 sticky；单位与换算口径必须在页内注明；合计行加粗顶线。

## 新视图 checklist

1. 数据只来自标准模型（或 bank 标准流水），不直接读 Excel
2. 复用 `html_page` / `kpi_cards` / `num_cell`，不自写页面骨架
3. 页面 JS 跑 `node --check`；测试断言零外链 + 关键数字存在
4. 无头 Chrome 渲染 PNG → 视觉审查代理按用户接受度验收，pass 才交付
5. demo 数据一律用星澜虚构数据集（或其衍生），真实数据不出本地私有目录
