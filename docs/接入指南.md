# 接入指南：把你家的导出文件接进 fin-workbench

目标：让引擎读懂你家的科目余额表导出文件。全程约 10 分钟，其中 AI 辅助约 2 分钟。

## 第一步 · 观察你的导出文件

打开导出的 Excel，确认四件事：

1. **表头在第几行**（金蝶常见为第 3-4 行，前面是公司名和期间）
2. **科目编码和名称**是分两列还是挤在一列（如 `1002　银行存款`）
3. **金额列的布局**：期初/发生/期末各是借贷分两列，还是正负号一列
4. **表尾**有没有合计行、制表人行（这些行会被自动跳过，但要让 mapping 知道特征词）

## 第二步 · 写 mapping.yaml

复制 `demo/mapping_jinDie.yaml` 改字段。全部可用字段：

```yaml
version: 1
name: <给你家格式起个名>
source:
  file: <默认数据源路径，可被命令行 --file 覆盖>
  sheet: <工作表名，留空取第一个>
  header_row: <表头所在行号>
  skip_patterns:           # A 列命中即跳过（正则）
    - 合计
    - 制表
  company: <公司名标注>
  period: <期间标注，如 2025-09>
unit_scale: 1.0              # 导出单位缩放：元=1.0；千万元=0.0001（导出即万元）
unit_note: 元
columns:
  code_name:                 # 编码名称同列时
    col: A
    split_regex: '^(\d+)\s+(.+)$'
  # 或者分列时：code: { col: A } / name: { col: B }
  opening: { debit: B, credit: C }
  period:  { debit: D, credit: E }
  closing: { debit: F, credit: G }
anchors:                     # 锚点清单，建议全开
  - opening_balance          # 期初借方合计 = 期初贷方合计
  - closing_balance          # 期末借方合计 = 期末贷方合计
  - codes_unique             # 编码无重复无空值
  - carry_forward            # 本月期初 = 上月期末（解析时传 --prev）
```

未映射的列（如"备注""币种"）引擎自动忽略。

## 第三步 · 解析并跑锚点

```bash
python -m fincore parse --config <你的mapping>.yaml \
  --file <导出文件>.xlsx --period 2025-09 \
  --prev out/上月.json --out out/本月.json
```

输出逐条锚点结果。**全绿才继续**；FAIL 的 detail 会告诉你是借贷差多少钱、
哪个科目与上月衔接不上 —— 通常是列配置错位或导出缺行，对照修正 mapping 即可。

## 第四步 · 出工作台

```bash
python -m fincore view-balance --model out/本月.json --out 余额台账.html
python -m fincore view-tax    --model out/上月.json --model out/本月.json --out 税费台账.html
```

## 常见问题

| 现象 | 原因 |
|---|---|
| `没解析到任何科目行` | header_row 不对，或科目列被 skip_patterns 误伤 |
| `科目列无法按 split_regex 拆分` | 编码名称的分隔符不是空白（如用 `-`），改 regex |
| `opening_balance FAIL，差额恰为某列合计` | 列映射错位（把合计列当科目列读入） |
| `carry_forward FAIL` | 上月数据不是同一套科目/同一导出口径，先统一 |
